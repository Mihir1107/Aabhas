Chapter 9

How it was evaluated, and how to reproduce it

Evaluation protocol

  • Split by lot, in production order. Train on lots 0–143, calibrate thresholds on 144–191, report on 192–239. modulea/evaluation.py returns lot ids, not row indices, so a row-wise split cannot be expressed.
  • Labels. Defective means Types I, II, III, IV and Vb. The traps are good, so flagging one costs yield.
  • Metrics. Recall and escape rate at a fixed yield loss (threshold set on good parts only), PR-AUC first and AUROC for comparability with ITC 2020, a 1000:1 cost for an escape against a scrapped part, and Wilson intervals on small classes. Accuracy is refused by the harness.
  • Fitting policy. Covariances and densities are fitted on good parts of training lots; the contaminated-fit variant is reported alongside. Module B trains on survivors of training lots and never on a latent value.
  • A self-tested harness. modulea/test_harness.py checks the metric code on cases with known answers, and statically checks that every runner calls functions that exist.

Stages run in order; each reads the previous one's output from results/.

pip install -r requirements.txt
python -m modulea.test_harness

The full chain takes about 20 minutes on a laptop. Module B records which gradient-boosting backend actually ran in results/module_b_provenance.json; this build used lightgbm 4.7.0 and quantile-forest. The dataset regenerates identically from its seed. A clean re-run of the whole pipeline reproduces every Module A figure exactly; only the quantile-forest rung moves, in the third decimal, from multithreaded tree building.
